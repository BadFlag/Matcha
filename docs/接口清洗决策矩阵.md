# Matcha Token 接口清洗决策矩阵

本文档记录阶段八之后的接口清洗边界。原则是先切断使用方，再调整测试约束，最后删除提供方；当前不直接大规模删除 `IThemeService`、`ITokenRegistry`、`NyanTheme` 的旧枚举 API。

## 三批执行计划

### 第一批：控件层清洗

目标是自绘控件不再把旧枚举 token 作为主样式入口。

已推进的小批次：

- `NyanBadge`
- `NyanMessage`
- `NyanNotification`
- `NyanSlider`
- `NyanRangeSlider`
- `NyanStatusBar`

这些控件的主绘制路径应满足：

- `paintEvent()` 通过 `Theme().Resolve(WidgetKind, variant, state)` 取得样式快照。
- 特殊语义色只通过 `Color("tokenKey")` 查询，并以 `ResolvedStyle` 字段作为 fallback。
- 不直接调用 `Color(ColorToken)`、`Font(FontRole)`、`Shadow(ShadowToken)` 作为主入口。
- 局部 `setStyleSheet()` 仅用于 Qt 原生子控件边界。

剩余第一批候选：

- `NyanDocumentToolBar`
- `NyanMainTitleBar`
- `NyanLogoButton`
- `DragGhostOverlay`
- `NyanStructureTree`
- 菜单/ActionBar 体系中的自绘控件

### 第二批：测试层清洗

目标是测试主断言转向 key 查询和 `Resolve()` 行为。

已覆盖方向：

- key 驱动控件样式字段测试。
- `Resolve()` key 优先路径测试。
- `shadowLayers` 多层保留测试。

后续要迁移：

- `ThemeTokenQueryTest` 中旧枚举兼容断言应缩减为 legacy/fallback 测试。
- `PaletteLoadTest`、`TonalPaletteTest` 应从 `ColorToken` 主断言迁到 `Color(key)`。
- `WidgetStyleSheetTest` 应从旧枚举默认字段断言迁到 key 字段断言。
- `TokenEnumsTest`、`DesignTokenTest` 在最终删除前标记为 legacy；删除枚举时同步删除。

### 第三批：主题 API 和兼容层清洗

删除顺序必须是：

1. 全仓控件主路径消费者归零。
2. 测试主断言迁移完成，仅剩 legacy/fallback 测试。
3. 删除 `IThemeService` 旧枚举 API。
4. 删除 `NyanTheme` 对应 override 和实现。
5. 删除 `Legacy*TokenKey` 映射。
6. 删除 `WidgetStyleSheet/StateStyle` 旧枚举 fallback 字段。
7. 最后删除旧枚举类型。

当前阻塞项：

- 菜单、ActionBar、Shell、Tooltip/WhatsThis 等路径仍直接使用 `ColorToken`。
- `ApplyGlobalStylesheet()` 仍为 Qt 原生控件生成 QSS，内部使用旧枚举。
- `SpaceToken` 仍是 `ContainerNode` 和 Demo 布局 API。
- 多个主题/树测试仍以旧枚举为主断言。

## 验证命令

每批修改后运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Matcha\Scripts\build-matcha.ps1 -Config Debug -Target MatchaThemeTests -Run -RunTarget MatchaThemeTests
```

辅助审计命令：

```powershell
rg -n "ColorToken::|FontRole::|ShadowToken::|SpaceToken::|RadiusToken::|Color\\(ColorToken|Font\\(FontRole|Shadow\\(ShadowToken" Matcha\Include Matcha\Source Matcha\Tests
```
